1. BACKGROUND

AI Codingが変える開発の仕事

コード生成の普及により、開発者の中心的な仕事は「一行ずつ書く」ことから、「意図・制約・検証を設計する」ことへ広がります。

コード補完
入力を支援

AIが得意な領域

03

2. MENTAL MODEL

Claude Codeの基本像

Claude Codeは、リポジトリと開発環境を文脈として利用し、指示に沿って調査・計画・実装・検証を進めるCLI型のコーディングエージェントです。

モデル

自然言語の依頼を解釈し、コードと資料から候補を推論する。

ツール

ファイル、検索、コマンド、Git、外部サービスを操作して仕事を進める。

ガードレール

権限、ルール、レビュー、テストで安全性と再現性を確保する。

重要：優れた出力は、モデルの能力だけでなく、渡す文脈と検証の設計で決まります。

3. AGENTIC LOOP

エージェントが仕事を進めるループ

一度の生成で終わらせず、観察と検証を次の行動に反映するループとして捉えます。

理解
依頼・制約を読む
調査
コードと履歴を確認
計画
変更範囲を決める
実装
小さく変更する
検証
テスト・差分を確認

良い依頼の材料

目的、対象範囲、受け入れ条件、触れてはいけない箇所、実行してよい検証。

ループの終了条件

テストが通るだけでは足りません。要件、差分、セキュリティ、運用影響を人が確認します。

5. CONTEXT

文脈を設計する：CLAUDE.md・Rules・Memory

CLAUDE.md

リポジトリで共有したい恒久的な前提を置く場所です。構成、起動方法、品質基準、禁止事項を短く明確に書きます。

Rules

特定の領域や作業に適用する決まりです。例：API変更時の互換性、UI変更時の確認観点。

Memory と Context

会話の流れや読み込んだ情報を活用します。必要な情報だけを渡し、古い前提を残さないことが重要です。

最初の改善

「どのコマンドで検証するか」と「変更してよい範囲」を明文化します。これは失敗を減らす効果が大きい一歩です。

07

6. EXECUTION

Plan Mode・Skills・Subagents

Plan Mode

実装前に、調査結果、変更案、リスク、検証方法を整理します。未知の変更ほど先に計画を読みます。

Skills

作業手順や専門知識を再利用する単位です。例：リリース手順、レビュー観点、社内APIの扱い。

Subagents / Teams

調査、実装、テストの役割を分けて並行化します。統合責任と最終レビューは人が明確に持ちます。

分割の基準：互いの編集範囲が重ならず、成果物の受け渡し条件を言語化できる仕事。
08

7. INTEGRATION & SAFETY

MCP・Plugins・Hooks・Permissions

MCP

外部ツールとの接続

チケット、設計資料、データ、社内サービスを、定義したインターフェース経由で利用します。

Plugin

機能の追加

特定の開発環境やサービス向けの能力を導入します。信頼できる提供元と権限を確認します。

Hook

イベント時の自動処理

実装前後や終了時に、整形、静的解析、記録などを組み込みます。

Perm.

実行権限の管理

読み取り、編集、コマンド、外部アクセスを分けます。最小権限と確認可能なログを基本にします。

外部接続は「何ができるか」よりも先に、「何を読めるか・書けるか・実行できるか」を確認します。

8. SDLC & TDD

SDLCに組み込むAI協業

要件
曖昧さ・受入条件を整理
設計
選択肢と影響を比較
実装
小さい差分を作成
テスト
失敗から修正を反復
レビュー／配布
人が判断し履歴を残す

TDDの使い方

先に期待動作をテストとして表現します。AIには、失敗するテストの原因分析と、最小の修正案を依頼します。

Gitの使い方

目的が一つの変更に絞られた差分を残します。AIの変更も、通常のレビューと同じ基準で確認します。

10. ROADMAP

五段階の学習ロードマップ

対話と安全な編集

小さな修正を依頼し、差分を読み、テストを自分で実行する。

文脈と検証の標準化

CLAUDE.mdとRulesを整え、プロジェクトの起動・検証手順を固定する。

計画とTDDの反復

Plan Modeで変更計画を確認し、テストを先に置いて実装を進める。

拡張と自動化

Skills、Hooks、MCPを小さく導入し、権限とログを確認する。

チーム運用

レビュー基準、役割分担、指標を整え、再現できる開発プロセスへ育てる。

11. MINI PROJECT

最初の実践：小さな機能追加

例：既存のToDoアプリに「完了済みを隠す」切り替えを追加する。

対象の画面、状態管理、テストの場所を調査する
表示条件と受け入れ条件を、短い仕様として確認する
Plan Modeで変更ファイルとテスト方針を先に確認する
失敗するテストを追加し、最小限の実装を依頼する
テスト、Lint、画面確認を実行して差分をレビューする
学んだ起動手順・注意点をCLAUDE.mdへ反映する
完了条件：機能が動くことに加え、変更理由・検証結果・次回への学びを説明できること。
13

12. TAKEAWAYS

学習の要点

「AIに実装を任せる」学習ではなく、
「AIが正しく働ける開発環境を設計する」学習です。

文脈

暗黙知を短いルールに変え、必要な情報だけを渡す。

検証

テストとレビューを、生成後ではなく作業の中心に置く。

段階導入

小さな変更から始め、実績を基に自動化と連携を広げる。

次の一歩：担当リポジトリを一つ選び、起動・検証・変更禁止領域をCLAUDE.mdに書き出す。
