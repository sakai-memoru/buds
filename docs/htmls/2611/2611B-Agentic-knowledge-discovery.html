LLM Agentic EngineeringCross-Domain Knowledge Discovery

LLMを質問応答の道具ではなく、目標・探索空間・評価ループを備えたAgentic Systemとして設計する。業際・学際の既知知識を抽象化・再結合し、意味のある新しい知識関係を探索するための考え方とアーキテクチャを示す。

中心命題：Context Engineeringは、単に必要な情報を投入する技術ではない。LLMが探索する知識空間、越えるべき領域境界、比較の抽象度、再結合の枠組み、選別基準を設計する技術である。

1. LLMをAgentic Systemとして捉える

Prompt EngineeringだけでLLM活用を捉えると、出力文の改善に議論が閉じる。実際のAgentは、目標を受け取り、文脈と記憶を使って探索し、必要に応じて外界を観測・変更し、結果を評価して経路を修正しながら、完了条件に至るまで動くシステムである。

Agentic System = Goal + Context + Memory + Reasoning + Tools + State + Evaluation + Loop

従来の見方

入力を受け、推論して、文章を返す。品質を主に一回の生成結果で判断する。

Agentic Systemの見方

目標に対して計画を立て、行動し、観測し、検証し、必要なら再試行する。LLMはその中の推論エンジンである。

2. Agentic Engineeringを構成する層

各層は相互に補完する。どれか一つだけを最適化しても、探索システム全体の性能は十分に上がらない。

一回の生成品質だけを追うのではなく、検証可能な部分を検証し、失敗の原因を次の行動へ戻す。コード生成なら「要件 → 生成 → コンパイル → テスト → エラー分析 → 修正 → テスト → 完了」となる。

基本思想：生成は確率的でも、検証できる部分は可能な限り決定論的にする。タスク、検証、フィードバック、再試行、停止条件をシステムとして設計する。

5. Cross-Domain Knowledge Discoveryの考え方

人間は自分の所属Domainに探索空間が局所化されやすい。同型の問題に対する解決原理が、Biology、Medicine、Cognitive Science、Economics、Control Engineering、Organisation Theory、Behavioural Scienceなどに存在していても、通常は到達しにくい。

重要な仮説：「解が存在しない」のではなく、「自分が探索しているDomain内に解が存在しない」場合がある。
Domain A
対象領域の問題
Domain B
異領域の原理・事例

単純な「A × B」では意味のある知識発見になりにくい。両領域を、機能・機構・構造・原理・一般パターンへ抽象化し、共通する構造を見出してから再結合する。これはキーワード類似ではなく、Structural Similarityの探索である。

抽象化の例

Software SystemとBiological Systemは表面上は異なるが、Boundary、Input / Output、Feedback、Adaptation、Redundancy、Failure、Recovery、Selectionといった共通構造を持ち得る。

Frameworkの役割

SCAMPER、ERCS、BMC、VPC、BSCは単なるテンプレートではない。HumanとAIが同じ探索座標系を共有するためのOntology、すなわち共通言語として使う。

6. 新しいKnowledgeを「Edge」として捉える

新しい知識は、必ずしも未知の知識Nodeを新設することではない。既知のNode同士のうち、未認識だった関係を発見することも、新しいKnowledge Discoveryになり得る。

Novel Knowledge = New Node とは限らない。
Novel Knowledge = Newly Discovered Relation / Edge である可能性がある。

Knowledge Graphを用いる場合、発見結果をNew Node、New Edge、New Pattern、New Abstractionとして記録できる。検証済みの関係と仮説段階の関係を分け、根拠・評価・反証条件も紐づけると、次の探索で再利用しやすい。

1. 分析から再結合まで

  • Problemを構造化し、対象Domainを定義する。
  • 関連する異業種・異学問Domainを探索する。
  • 原理、パターン、理論、事例、Frameworkを取得する。
  • 固有表現を除き、共通Structureへ抽象化する。
  • 構造的に対応する候補だけを再結合する。

2. 仮説から再探索まで

  • Problem Solution、Theory、Design Hypothesisを生成する。
  • Novelty、Utility、Feasibility、Consistency、Testabilityを評価する。
  • 有望なKnowledge、失敗した組合せ、評価結果を記憶する。
  • 不足するDomainや根拠を特定し、探索を再開する。

9. Human-in-the-Loopの役割分担

Humanが担うこと

  • Problem Framing：何を問題と定義するか。
  • Goal Setting：何を良い状態とするか。
  • Value Judgment：人間・社会・Businessに意味があるか。
  • Final Selection：どのHypothesisを採用するか。

AIが担うこと

  • Search Space Expansion：他Domainへ探索領域を広げる。
  • Retrieval / Abstraction：類似原理・事例を探し、共通構造を取り出す。
  • Recombination：構造的に適合する知識を組み合わせる。
  • Simulation / Criticism：仮説を評価・批判し、再探索を支援する。
Human Goal → AI Exploration → Human Judgment → AI Re-exploration

結論

Prompt Engineeringが問いを設計し、Context Engineeringが探索空間を設計する。Knowledge Engineeringが知識構造を、Reasoning / Planningが探索経路を、Tool Engineeringが探索可能世界を、Evaluationが良い発見を、Memoryが探索結果を、Loopが探索過程を設計する。Harness Engineeringは、それらを一つのAgentic Systemとして統合する。

この設計思想の狙いは、単なるアイデア生成ではない。業際・学際の既存知識から、構造的に意味のある新しいKnowledge Relationを発見し、根拠と検証可能性を伴う仮説として蓄積・改善することである。
